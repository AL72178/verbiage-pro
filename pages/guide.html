Current Website Features

What the current app supports

These are the behaviors that are live in the current UI, including the newer abbreviation review flow.

Navigation and Search

Tabs are generated from Inquiry. Search checks Inquiry, Secondary Category, Scenario, Decision Code, Short Summary, and Verbiage.

PDR Filter

PDR + Custom Verbiage shows everything. Only PDR Verbiage shows only rows where Coded By is pdr, ignoring case.

Row Actions

Copy copies the selected row text. Break sends that row into Letter Break and starts chunking immediately.

Abbreviation Review

Apply Abbrev shows a status panel while processing, then explains what changed or asks the user to choose a meaning when a term is ambiguous.

Data Structure

Managing Data in data/Data.json

The main verbiage library is stored in data/Data.json. The app expects a JSON array using the structure below.

Required JSON structure 
[
  {
    "Inquiry": "Category Name",
    "Secondary Category": "Sub-Category Name",
    "Scenario": "Specific Context",
    "Short Summary": "Brief description of the response",
    "Decision Code": "Unique Short Code. E.g. AECNR",
    "Verbiage": "The actual response text.",
    "Coded By": "pdr or user"
  }
]

Inquiry

Top-level category. This creates the tabs shown in the app.

Secondary Category

Second level grouping inside the main inquiry.

Scenario

The exact use case for the response.

Short Summary

A quick description users can scan in the table.

Decision Code

Short reference code shown for the entry.

Verbiage

The response text itself. This can include editable placeholders.

Coded By

Use pdr for official templates. Any other value, or leaving it blank, is treated as custom verbiage.

Editable Fields

Verbiage formatting rules

Editable placeholders let agents personalize text directly in the table without removing the surrounding brackets.

Rule

Place * right after the opening bracket.

The current renderer supports all three bracket styles: [], (), and {}.

Examples

[*Customer Name]

(*Object Name)

{*Approval Status}

Example verbiage
"Verbiage": "Hello [*Customer Name], your request for (*Object Name) has been {*Approval Status}."

What stays visible

The brackets remain visible and help protect the structure.

What becomes editable

The text after the * becomes editable in the UI.

What does not change

Normal text such as (EOB), (AD), or document(s) stays untouched because it does not contain the * marker.

Letter Break Workflow

Letter Break and Apply Abbrev

Use this area for final cleanup, copy-ready chunks, and abbreviation formatting before you send or paste the final text.

Letter Break

Chunk and reset text fast

Divide Text splits content into 63-character chunks without breaking words when possible.

Reset clears the textarea, generated output boxes, and any active abbreviation review state.

The row-level Break button sends selected table verbiage into Letter Break automatically.

Apply Abbrev

Expand first mentions and review ambiguous terms

Apply Abbrev checks the Letter Break text against data/Abbreviation.json.

If a term has one meaning, the first occurrence becomes Full Form (ABBR).

Later occurrences become (ABBR) if they are not already wrapped.

Terms with special characters, such as E/M, are supported.

If the text already contains Full Form (ABBR), that expansion is preserved and later repeats are wrapped.

If a term has multiple meanings, the app shows clickable options so the user can choose the correct one.

A status panel appears while processing and after completion so users can review what changed.

Abbreviation file format in data/Abbreviation.json 
[
  {
    "Term": "CMS",
    "Definition": "Centers for Medicare & Medicaid Services",
    "Definition 2": "Claims Management System",
    "Definition 3": ""
  }
]

Use Term for the abbreviation itself.

Use Definition, Definition 2, and Definition 3 for possible meanings.

Leave unused definition fields blank.

If more than one unique definition is present, the app shows manual selection choices during review.

Custom Request Option

Submit your own verbiage

If the library does not already have the wording you need, send a request to nishant.singh@carelon.com.

What to include

The goal is to make the request easy to review and easy to convert into data/Data.json.

Inquiry is the top-level category used to create tabs in the app.

Include Secondary Category if the new entry should appear under a specific subgroup.

If the verbiage needs editable fields, use [*Field Name], (*Field Name), or {*Field Name}.

If a new abbreviation is needed too, include the abbreviation and its full form in Reason / Notes.
